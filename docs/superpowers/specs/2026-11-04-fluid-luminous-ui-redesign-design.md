# Fluid Luminous UI 重构设计规范

日期：2026-11-04
状态：待用户审阅

## 1. 目标

在不改变现有业务能力、HTTP API、SQLite 数据模型、稳定 ID 和页面职责的前提下，重做三个页面的 UI 表现：

- 仪表盘
- 订单复盘
- 设置

视觉方向采用 Fluid Luminous：深色流体背景、分层半透明玻璃、边缘高光、缓慢流光和有限的浮动动效。现有功能入口和交互流程继续可用。

## 2. 范围与边界

### 2.1 页面范围

订单复盘是订单列表、订单详情、截图阅读、复盘编辑、精选、随机阅读、打卡和归档能力的统一工作区。画册不新增为独立业务页面；现有兼容入口继续指向订单复盘。

### 2.2 保留内容

- 现有页面信息架构和主要功能入口；
- MT5 与国内期货平台工作区切换和平台隔离；
- 现有 API 路由、字段名称、稳定 ID 和服务端指标口径；
- 订单列表与订单详情的联动关系；
- 现有加载、空、警告、错误、不可用和禁用语义；
- 现有布局编辑、筛选、分页、截图、复盘、导入、清理和备份流程。

### 2.3 不在本次范围

- 新增业务实体、指标或数据库字段；
- 改变统计定义、时区和平台能力声明；
- 将画册重新拆为独立业务页面；
- 引入前端构建工具或第三方 UI 框架；
- 把本地服务暴露到公网。

## 3. 数据与状态边界

数据库仍是唯一业务事实来源。UI 只保存临时状态，例如当前页面、当前选中订单、浮卡展开状态、筛选控件状态和布局编辑状态。

任何订单、Position、Campaign、分类、自定义字段、标签、复盘文本和截图信息都通过现有服务端返回值与稳定 ID 读取；不会创建页面专属副本或生成替代 ID。

本次不新增派生视图，因此：

- entity owner：现有服务端实体，不新增 owner；
- data source：现有 SQLite/API；
- rebuild rule：不适用；
- platform scope：沿用现有 MT5/domestic_futures 能力声明；
- cross-view test path：订单写入后通过订单列表、订单详情、仪表盘和现有兼容入口读取同一记录。

## 4. 视觉系统

### 4.1 层级

1. Atmosphere：页面背景和慢速流体光，变化最慢。
2. Base Glass：普通模块、筛选栏、表格容器。
3. Clear Glass：主指标、图表、订单详情和主要内容区。
4. Fluid Luminous：当前焦点、洞察卡、选中项、重要操作和高强光标签。

### 4.2 背景

- 使用蓝黑色而不是纯黑色作为基础背景；
- 使用青色、蓝紫色、少量绿色和琥珀色大型模糊光源；
- 光源周期约 18 至 30 秒；
- 持续动画只改变 transform/opacity，不持续动画 backdrop-filter；
- 页面切换不重复播放大范围背景动画。

### 4.3 玻璃材质

Base Glass 使用半透明深色背景、中等模糊、细边框和顶部高光线。

Clear Glass 增加背景透色、亮边框、内阴影和轻微环境光，用于图表和订单详情。

Fluid Luminous 使用多层渐变、亮边框、内部光带、内发光和 2 至 5px 的轻微浮动，只用于当前焦点和洞察区域。

在不支持 backdrop-filter 的环境中提供不透明背景回退。

### 4.4 颜色语义

- 青色：当前焦点、选中、链接和导航；
- 蓝紫色：策略、分析和洞察；
- 绿色：盈利、完成和成功；
- 琥珀色：待处理、警告和风险提示；
- 红色：亏损、失败和危险操作；
- 冷灰色：归档、停用和不可用。

颜色不能是唯一状态依据，必须同时使用文字、图标或状态标签。

## 5. 统一组件

### 5.1 Glow Pills 标签

交易场景、交易策略、犯错标签、自定义字段标签、订单状态、精选和归档状态全部使用同一套高强光半透明玻璃药丸。

- 正常标签：半透明填充、语义色边框和柔和光晕；
- 选中标签：增加边缘光和内高光；
- 停用标签：降低饱和度，但保留形状和结构；
- 标签可包含图标、文本和移除按钮；
- 标签文字必须在窄屏内换行或截断，不得撑开布局。

### 5.2 Glass Menus 下拉菜单

平台、状态、排序、日期预设、字段类型、筛选条件和布局选项统一使用玻璃菜单。

- 菜单悬浮展开，不改变页面布局高度；
- 当前选项使用高亮背景和勾选图标；
- 支持键盘焦点、上下移动、Enter 选择和 Esc 关闭；
- 移动端使用底部弹层或全宽菜单；
- 原生 select 的语义和表单提交能力必须保留，视觉层通过统一包装实现。

### 5.3 页面壳与模块

- 应用壳保留导航、平台切换、刷新/导入和页面标题；
- 当前导航项使用青色边缘光；
- 模块统一标题、说明、操作区和状态区；
- 页面大区不再额外嵌套无意义卡片；
- 表格容器使用玻璃材质，表格行保持清晰稳定；
- 弹窗使用更高层级 Fluid Luminous 材质和遮罩；
- 图标继续使用本地 Lucide 资源。

## 6. 页面设计

### 6.1 仪表盘

顶部保留页面标题、平台切换、时间范围、日期筛选、刷新/导入和布局编辑。

MT5 与国内期货模块继续使用现有模块注册和布局编辑能力。模块统一套用玻璃卡片，指标重点区可以使用 Clear Glass，当前解释或关联提示使用可收起浮卡。

模块状态必须覆盖 loading、value、empty、warning、error、unavailable、insufficient、incomplete、estimated 和 not applicable。单模块错误不能遮蔽其他模块。

移动端使用单列模块、可横向滚动的筛选栏和底部洞察抽屉；布局编辑进入独立编辑状态。

### 6.2 订单复盘

订单复盘保持订单列表和订单详情同页联动：

- 顶部保留时间筛选、订单状态、全部/精选、随机阅读等入口；
- 左侧订单列表独立滚动和继续加载；
- 右侧订单详情以交易截图作为第一视觉层；
- 交易摘要、标签和复盘状态使用可收起的 Fluid Luminous 浮卡；
- 复盘文字编辑器保持独立滚动和长文本可用性；
- 截图放大、关闭、缩放和原图比例继续可用；
- 打卡日历位于主工作区下方并保持独立状态；
- 精选、随机阅读、归档和恢复继续属于该工作区。

浮卡在选中订单、点击摘要/标签/复盘状态或从关联入口进入指定订单时展开。点击外部区域、关闭按钮或 Esc 收起。移动端使用详情全屏和底部摘要抽屉。

### 6.3 设置

设置保留分类与字段、分析设置、数据与状态三个标签。

分类与字段使用稳定的高密度玻璃面板；字段新增、编辑和选项配置使用统一弹窗、标签和下拉菜单。

分析设置保留 Scratch 阈值输入、范围校验和保存状态。

数据与状态保留 CSV/XLS 导入、模板下载、导入摘要、问题明细、未匹配成交、批次历史、批次撤销、数据清理预览/确认、状态刷新和备份创建。

导入、清理和备份等高风险操作使用明确的结果卡和确认层，降低持续动效，避免误操作。

## 7. 动效与无障碍

- 页面进入：标题、工具栏和模块按顺序轻微淡入；
- 卡片展开约 220ms，收起约 160ms，hover 约 160ms；
- 浮动卡片只做 2 至 5px 的轻微呼吸位移；
- 图表只做一次加载过渡，不循环播放数据动画；
- prefers-reduced-motion 时关闭持续流光、浮动和大范围入场动画；
- 不依赖 hover 作为唯一交互入口；
- 保留 :focus-visible 高亮、ARIA 名称、键盘关闭和可见错误信息；
- 不允许动画造成横向溢出、布局跳动或滚动卡顿。

## 8. 实施顺序

### 阶段 A：共享视觉基础

更新 tokens、base、components 和 shell，建立背景光、玻璃层级、Glow Pills、Glass Menus、浮卡、状态和动效基础。

### 阶段 B：订单复盘

先改订单复盘，因为它同时验证列表、详情、截图、标签、编辑器、弹窗、浮卡和移动端抽屉。

### 阶段 C：仪表盘

将共享模块皮肤应用到 MT5 和国内期货模块，保持模块注册、指标状态和布局编辑契约。

### 阶段 D：设置

统一设置标签、表单、下拉、导入审计、清理确认、状态和备份组件。

### 阶段 E：回归与发布门禁

执行现有 Python/Node 测试、前端语法检查、桌面端和 390px 浏览器回归、控制台错误检查、横向溢出检查和发布版本文档同步。

## 9. 验收标准

- 三个页面现有功能入口全部保留；
- 订单列表和订单详情仍在同一工作区联动；
- 交易截图在桌面端和移动端都是订单详情的第一视觉层；
- 所有标签使用 Glow Pills；
- 所有下拉菜单使用 Glass Menus；
- 模块覆盖加载、空、警告、错误、不可用和禁用状态；
- 桌面端和 390px 移动端无横向溢出或内容重叠；
- 现有 API、字段、稳定 ID、平台隔离和指标口径不改变；
- reduced-motion 和无 backdrop-filter 回退可用；
- 现有测试和新增视觉回归检查通过。

## 10. 暂不实现的决定

本规范确认后仍需单独编写实施计划。实施计划批准前不修改业务代码、不改变 API、不新增数据库字段。
