# ADR-0005：共享业务数据的单一来源与跨页面一致性

## 状态

已接受

## 背景

项目包含订单流水、分析仪表盘和复盘画册等多个页面。它们的展示重点不同，但面向的是同一平台、同一批交易数据。页面之间如果分别保存交易场景、交易策略、犯错标签或复盘内容，就会出现一个页面已经保存、另一个页面仍显示未分类的分裂状态。

SQLite 文件统一并不自动代表数据统一。必须同时统一业务数据的归属实体、字段名、值格式和稳定 ID。

## 决策

1. SQLite 是平台范围内业务数据的唯一来源；页面只能展示和操作持久化业务记录，不得为同一业务概念建立页面私有副本。
2. 每类数据必须有唯一拥有者：
   - Campaign 是用户侧唯一订单，拥有订单级交易盈亏、手续费、净盈亏、精选状态、打卡关系、复盘分类、策略、犯错标签、复盘文字和订单级自定义字段；
   - Position 拥有独立持仓风险和初始止损；
   - Trade/Deal 拥有来源成交和审计字段。
3. 页面之间使用稳定的 `campaign_id`、`position_id`、`trade_id` 关联，不根据当前页面重新生成 ID，也不使用不同名称表示同一字段。
4. 其他页面需要展示拥有者数据时，必须通过关系读取拥有者记录。允许存在缓存或投影，但必须有明确的拥有者、刷新/重建规则和失效处理，并且不能被当作独立数据源。
5. 共享数据功能必须有跨页面测试：从拥有者页面写入，再从其他页面和相关 API 读取相同字段、值和 ID。
6. 所有用户侧订单统计以 Campaign 为一笔订单。Campaign 内的 Trade、Position 和 Deal 不得重复计入订单数、胜率、盈亏比、收益曲线、月度统计或合约榜单；它们只在订单详情的成交流水中展开。
7. 精选状态写入 `trade_campaigns.is_featured`，打卡写入 `campaign_checkins(campaign_id, checkin_date)`；旧的 Trade 级字段和打卡表仅用于迁移与兼容读取。

## 影响

- Campaign 级标签不能只写入 Campaign 后又让画册读取 Trade 级标签。
- 仪表盘必须读取组合级分析行；不能因为手续费、月度盈亏或合约榜单仍读取 Trade 而把同一订单再次拆分统计。
- 订单复盘可以在成交流水中展示源 Trade/Deal，但列表、复盘截图、精选、打卡和统计必须使用 Campaign。
- 数据模型、API、序列化器和前端状态的字段名必须保持一致；兼容旧字段时必须定义唯一规范字段和迁移规则。
- 任何违反该决策的变更都必须先更新本 ADR，并说明为什么不能复用已有业务记录。

## 验收要求

- 订单页面保存的交易场景、策略和犯错标签，在画册和仪表盘相关展示中读取到相同值；
- 同一订单在所有页面使用同一 `campaign_id`，其来源成交使用同一 `trade_id`；
- 重建 Campaign、刷新页面和切换工作区不会产生第二份分类或标签数据；
- 跨页面测试覆盖成功保存、重新读取、清空标签和模型重建后的读取结果。
