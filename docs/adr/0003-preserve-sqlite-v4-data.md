# ADR-0003：保持现有 SQLite 数据模型并进行兼容迁移

- 状态：接受
- 日期：2026-09-02
- 关联设计：[`docs/superpowers/specs/2026-09-02-architecture-redesign-design.md`](../superpowers/specs/2026-09-02-architecture-redesign-design.md)（ADR-003）

## 背景

历史订单、截图、复盘内容、交易分类、自定义字段和 Campaign/R 口径不可丢失，也不能要求用户人工导入或重建。架构改造不应破坏已积累的真实数据。

## 决策

架构改造阶段继续使用现有 SQLite 数据库和 schema v4，仅通过版本化、事务化、可回退的迁移增加必要索引或元数据：

- 迁移在事务中执行，升级前使用 SQLite Backup API 创建本地快照；
- 迁移失败时回退到旧数据和旧版本，不留半迁移状态；
- 架构改造期间不移动真实数据目录；
- 历史 v2/v3/v4 合成 fixture 通过幂等迁移升级并通过审计。

## 后果

### 正面

- 数据风险最低，用户无感知升级。

### 负面

- 新仓储必须兼容历史字段，不能随意假设理想化的新表结构。

## 被否方案

- **重建新数据库并转换**：需要用户人工介入且风险高。
- **迁移到其他数据库**：改变运行依赖，与单文件、标准库定位不符。
