# ADR-0004：Windows 封装后置，但现在建立兼容边界

- 状态：接受
- 日期：2026-09-02
- 关联设计：[`docs/superpowers/specs/2026-09-02-architecture-redesign-design.md`](../superpowers/specs/2026-09-02-architecture-redesign-design.md)（ADR-005）

## 背景

最终目标是把本项目做成 Windows 11 桌面软件，但当前首要问题是代码架构耦合。过早封装会把路径、启动和状态问题固化进安装包，使后续重构更困难。

## 决策

v0.6.0 完成路径配置、本机监听和模块边界；下一阶段再增加 WebView2 桌面壳与安装程序。本次交付完成：

- 程序目录与数据目录解耦，支持通过环境变量重定向数据/配置根目录而不移动旧数据；
- 服务默认只监听 `127.0.0.1`，局域网访问必须显式开启；
- 稳定的四层模块边界，使后续桌面化无需重写业务层。

## 后果

### 正面

- 本次仍以浏览器运行方式验收，但后续桌面化无需重写业务层。
- 避免过早把路径和启动逻辑固化进安装包。

### 负面

- 用户在本版本仍需通过浏览器访问，桌面体验延迟到下一阶段。

## 被否方案

- **Electron**：引入重量级运行依赖，与标准库、无构建定位不符。
- **本次同时交付安装包**：会在架构尚未稳定的情况下固化路径与状态问题。
