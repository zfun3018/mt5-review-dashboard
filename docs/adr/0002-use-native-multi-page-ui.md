# ADR-0002：前端采用原生多页面与 ES Modules

- 状态：接受
- 日期：2026-09-02
- 关联设计：[`docs/superpowers/specs/2026-09-02-architecture-redesign-design.md`](../superpowers/specs/2026-09-02-architecture-redesign-design.md)（ADR-002）

## 背景

复盘仪表盘、订单列表、复盘画册三个页面的加载内容和工作流明显不同，但此前的单一脚本与全局状态把它们耦合在一起，首页还会同时读取分析、Campaign 列表、设置和订单详情。项目没有前端构建依赖，也无意为此引入运行期工具链。

## 决策

使用共享应用外壳加四个页面入口，每页拥有自己的控制器和状态，公共能力通过原生 ES Modules 复用：

- 分析仪表盘 `/dashboard/`
- 订单流水 `/orders/`
- 复盘画册 `/album/`
- 设置与系统 `/settings/`

共享模块位于 `web/shared/`：设计令牌与通用组件（`css/`），请求、外壳、格式化、反馈和 URL 状态（`js/`）。根路径 `/` 是兼容重定向壳，把旧深链映射到新页面。

## 后果

### 正面

- 页面首屏载荷和状态复杂度下降，每页只加载自身入口模块。
- 不需要 Node 构建或前端框架即可运行。

### 负面

- 共享体验必须通过设计令牌和组件规范保持一致，否则页面间会出现风格漂移。

## 被否方案

- **SPA 框架（React/Vue）**：迁移成本高，且与当前规模和无构建依赖的定位不符。
- **继续在单页内打补丁**：无法消除页面间数据互相牵连的问题。
