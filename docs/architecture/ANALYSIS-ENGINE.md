# 分析引擎边界

## 目标

分析引擎负责把 Campaign 事实转换为可解释、可验证、可重建的统计报告。它不拥有交易事实，也不改变订单复盘页面的布局和业务含义。

## 单一事实源

`Campaign` 是全系统唯一业务订单，也是仪表盘的默认统计单位。数据流为：

```text
Deal / 成交导入
        ↓
Position / 成交重建
        ↓
Campaign / 合并后的业务订单
        ↓
订单复盘、仪表盘、精选、打卡和其他报告
```

仪表盘不直接以 Deal 或 Position 作为订单统计来源。成交流水可以在订单详情中展开，但不能让同一个 Campaign 在仪表盘中被重复计数。

## 运行时边界

```text
CampaignRepository
        ↓ 规范化 Campaign 行
AnalysisContext
        ↓ 统一时间窗口、时区、平台能力和数据质量
Metric modules
        ↓ MetricResult
AnalysisReport
        ↓ 兼容 API 响应
/api/analysis
        ↓
dashboard.mjs / charts
```

### 数据层

`CampaignRepository` 负责从 SQLite 读取有效的 Campaign、快照、分类目录和必要的关联数据。它不能生成页面专用别名，也不能把仪表盘结果写回交易事实表。

### 领域层

领域模块只接收内存中的规范化数据和配置，负责公式、分组、日期转换和数据质量判断。它不能导入 SQLite、HTTP、文件系统或 DOM。

### 应用层

`DashboardService` 负责加载一次分析上下文、选择指标模块、组装报告和保持旧 API 兼容。它不应该重新实现任何指标公式。

### 前端层

前端只负责卡片、表格、图表、状态和下钻链接。前端不能根据原始 Campaign、Position 或 Deal 重新计算净盈亏、订单数或胜率。

## 当前基线

当前仪表盘已有模块和口径记录在 `docs/metrics/README.md`。迁移到指标注册表前，现有领域函数的数值视为兼容基线；重构不应无说明地改变历史统计结果。

## 派生结果与重建责任

| 结果 | 所有者 | 来源 | 重建触发与规则 | 平台范围 | 跨页面验证 |
| --- | --- | --- | --- | --- | --- |
| Deal / 原始成交 | 导入事实表 | MT5 事件或国内期货导入行 | 导入批次提交时写入；重复事实按稳定来源键幂等 | 平台隔离 | 导入批次、成交流水、Campaign |
| Position | `positions` 派生模型 | `deal_events`，旧版交易按兼容规则估算 | 成交事实变化或迁移时重建；真实成交字段优先于估算字段 | `platform + account + position_id` | 订单详情与 Campaign 位置明细 |
| Campaign | `trade_campaigns` 业务聚合 | Position 关系和成交事实 | 关联事实变化时重建；保留用户复盘字段，不以估算值覆盖真实执行事实 | 平台范围内按稳定 Campaign ID 聚合 | 订单、画册、打卡、仪表盘和相关 API |
| 仪表盘指标 | `MetricResult` / `/api/analysis` 派生投影 | Campaign、时间窗口、平台能力和设置 | 请求时可重建；公式改变必须增加 `definition_version`，不回写业务事实 | 当前 AnalysisContext 平台 | 订单 Campaign 合计、日报、月历和下钻筛选 |

用户拥有的复盘文字、分类、错误标签、截图引用、自定义字段和打卡记录属于业务注释，所有重建都必须保留它们。交易盈亏、手续费、时间和成交关系属于导入事实或可从事实重算的聚合字段；估算的旧数据重建只能标记为估算，不能覆盖真实成交结果。

任何新增派生视图都必须在实现前声明实体所有者、数据来源、重建规则、平台范围和跨页面测试路径。指标模块只读取内存中的 `AnalysisContext`，不得把结果持久化为第二份业务数据。

## 非目标

- 不把仪表盘改造成图片浏览器；
- 不把指标结果作为新的业务数据持久化；
- 不为每个平台复制一套通用统计公式；
- 不为假设中的大数据量提前引入缓存、数据仓库或分布式服务；
- 不在指标引擎中加入 AI 判断或交易建议。
