# 数据重建与派生结果规则

## 责任边界

- 原始成交、MT5 事件和导入行是不可替代的输入事实；导入批次记录来源、重复、无效和未配对数量。
- `Campaign` 是业务订单和复盘字段的唯一所有者。它通过稳定 ID 关联 Position 和源交易，不由页面另存一份。
- Position、Campaign 汇总和仪表盘指标是可重建结果。它们可以从成交事实和持久关系重新生成。
- `/api/analysis` 是派生响应，不是新的事实表。页面不得把展示结果写回交易或 Campaign 表。

## 重建规则

1. 成交事实变化、导入批次提交或数据库迁移后，按平台隔离重建 Position 和 Campaign 关系；必要时可全量重建以恢复分组正确性。
2. 重建使用稳定的 `platform + account + position_id` 和 Campaign 关系。重复导入不得创建重复源成交、重复 Position 或重复 Campaign。
3. 重建可以重新计算成交盈亏、手续费、swap、fee、时间聚合和风险结果，但必须保留用户拥有的 `review_text`、分类、错误标签、截图引用、自定义字段和打卡记录。
4. 只有成交事实能够证明的值才可覆盖事实字段。旧版兼容模型产生的 `legacy_estimated` 结果必须带估算状态，不能覆盖后来导入的真实 Deal/Position 数据。
5. 指标结果按请求从 Campaign 重算。公式、时间字段、时区或样本口径变化时，增加指标 `definition_version`，不修改历史业务事实。

## 导入、失败与备份

- 每个导入批次在一个事务中提交；解析、校验或写入失败必须回滚业务写入，并把批次标记为 `failed`。
- 成功导入的重复行应计入重复统计但不重复生成业务订单；同一导入再次执行后的 Campaign 数量和分析净盈亏必须不变。
- 数据库迁移在升级前创建备份。原始成交、Campaign 复盘字段和派生指标承担不同备份责任：原始成交与用户注释必须可恢复，派生指标可由恢复后的事实重新计算。
- 备份和迁移测试只使用合成 fixture；不得读取或提交本机 `data/`、`backups/`、配置、原始 JSONL、截图或生成二进制。

## 兼容与验收路径

旧 `/api/analysis` 字段继续由应用层从 `MetricResult` 组装，新增元数据只能通过可选 `metric_meta` 提供。迁移或重建后的验证顺序是：

```text
事实/导入批次
→ Campaign 与订单 API
→ 画册、打卡和复盘字段
→ /api/analysis 派生指标
→ 订单合计、日报、月历和平台隔离对账
```

任何跨表重建都必须有迁移测试；任何指标模块都必须有指标契约、合成数据测试和至少一个订单与仪表盘的跨视图对账测试。
