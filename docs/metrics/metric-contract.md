# 指标契约

## 目的

仪表盘指标必须可以脱离页面复核。每个指标都需要说明输入来源、统计口径、公式和数据质量；页面只负责展示结果，不自行推导交易事实。

## 必填字段

指标目录中的每一行必须声明：

- `key`：稳定的接口和注册表标识；
- `owner`：负责计算的领域模块；
- `unit`：金额、比例、数量、时间或混合结果；
- `statistical_unit`：统计对象是 Campaign、Position、Deal 或明确的混合对象；
- `time_field`：用于筛选和分组的事实时间字段；
- `timezone`：日期和时段计算使用的时区；
- `definition_version`：公式和输入口径的版本；
- `test_path`：独立验证该指标的测试文件。

指标说明还必须补充以下内容：

- 公式和中间值；
- 输入字段和数据所有者；
- 手续费、swap、fee 是否包含；
- 盈利、亏损和打平的判定；
- 缺失数据处理；
- 最小样本量；
- 小数和四舍五入规则；
- 适用平台与不适用平台；
- 订单复盘下钻筛选；
- 变更时的迁移和兼容策略。

## 结果状态

指标结果不能把未知状态编码成 `0`。统一使用以下状态：

| status | 含义 | 页面行为 |
| --- | --- | --- |
| `available` | 数据完整且样本足够 | 显示数值 |
| `insufficient_data` | 样本量低于指标要求 | 显示样本不足 |
| `incomplete_data` | 必要字段缺失或重建不完整 | 显示数据不完整 |
| `estimated` | 基于可选市场数据或其他近似输入 | 显示估算标记和限制 |
| `not_applicable` | 当前平台或数据类型不支持 | 显示不适用 |

## 统计原则

1. 订单数默认按 Campaign 计数。
2. 已实现盈亏默认使用 Campaign 的净盈亏；不能在仪表盘各模块重新从 Deal 相加。
3. 日历和时段使用统一的时间字段和时区。
4. 互斥分类的分组总数可以与总订单数对账。
5. 多选标签允许一笔 Campaign 出现在多个标签分组中，必须说明这是标签出现次数。
6. 精选、打卡和复盘完成度属于复盘行为，不得混入交易表现指标。
7. 公式变化必须增加 `definition_version`，历史结果按版本解释。

## 新指标验收

新指标必须经过以下检查：

```text
指标说明
→ 合成数据手工预期
→ 领域函数单元测试
→ /api/analysis 响应测试
→ 与 /api/campaigns 的跨视图对账
→ 样本不足和缺失数据测试
→ 前端状态渲染测试
```
