# v0.5.8 → v0.6.0 数据迁移操作手册

适用对象：MT5 复盘仪表盘 v0.5.8（主仓 `F:\文件\MT5复盘仪表盘\mt5-review-system\`）升级到 v0.6.0（重构 worktree `codex/v06-architecture-redesign`）。

## 1. 为什么需要这份手册

v0.6.0 重写了后端（模块化单体拆分），但**所有数据 schema 都是 v4**。两版本数据库 schema 完全兼容，只是代码与 UI 重构。本手册让你在不复制 6 MB 数据库的前提下，把 v0.6.0 新代码接到 v0.5.8 已经积累的真实交易数据上。

## 2. 备份（必做）

执行任何迁移前，先备份 v0.5.8 的 data 目录与 config.local.json：

```bash
mkdir -p F:/文件/workbuddy_dato/MT5复盘项目/backups/v05-to-v06-2026-09-04
cp -r "F:\文件\MT5复盘仪表盘\mt5-review-system\data" \
      "F:\文件\workbuddy_dato\MT5复盘项目\backups\v05-to-v06-2026-09-04\data-backup"
cp "F:\文件\MT5复盘仪表盘\mt5-review-system\config.local.json" \
   "F:\文件\workbuddy_dato\MT5复盘项目\backups\v05-to-v06-2026-09-04\config.local.json.backup"
```

验证备份成功：

- `data-backup/journal.sqlite` 存在，sqlite 头 100 字节包含 `SQLite format 3`。
- `data-backup/screenshots/` 至少与 v0.5.8 原目录等量的 PNG。
- `config.local.json.backup` 是有效 JSON。

## 3. 关闭 v0.5.8 实例

如果 `start.ps1` 还在运行，先在 PowerShell 中停掉：

```powershell
Get-Process python -ErrorAction SilentlyContinue | Where-Object { $_.Path -like '*\mt5-review-system\*' } | Stop-Process -Force
Get-NetTCPConnection -LocalPort 8787 -ErrorAction SilentlyContinue
```

期望输出为空（8787 端口已释放）。

## 5. 启动 v0.6.0，指向 v0.5.8 数据

v0.6.0 的 `RuntimePaths.from_environment()` 已原生支持外部数据目录，通过两个环境变量指向 v0.5.8 现有数据：

```powershell
cd F:\文件\MT5复盘仪表盘\.worktrees\v06-architecture-redesign\mt5-review-system

$env:MT5_REVIEW_DATA_DIR     = 'F:\文件\MT5复盘仪表盘\mt5-review-system\data'
$env:MT5_REVIEW_CONFIG_FILE  = 'F:\文件\MT5复盘仪表盘\mt5-review-system\config.local.json'
$env:MT5_REVIEW_HOST         = '127.0.0.1'
$env:MT5_REVIEW_PORT         = '8787'

python run.py
```

或者使用项目自带的 `start-with-existing-data.ps1`（已附在本目录），一次性完成上述设置。

## 6. 验证迁移成功

启动后浏览器打开 `http://127.0.0.1:8787/`，应当看到：

1. **导航栏**：四个 workspace（Dashboard / Orders / Album / Settings）；
2. **Dashboard 指标卡片**显示真实数据：
   - 总交易数：**105**（非 7 demo）
   - 胜率、平仓盈亏、Z 分数、R 期望等；
   - 资金曲线 13146 个真实快照点；
3. **Orders 页面**：所有 105 条交易按时间倒序排列，标的最早到 2026-08-14，最新到 2026-09-03；
4. **Album 页面**：105 张真实截图按时间/品种/盈亏可筛选；
5. **Settings 页面**：MT5 安装路径、bridge 目录与 `config.local.json` 一致。

命令行快速校验：

```powershell

```

预期：`/api/health` 返回 `{"status":"ok"}`；`/api/analysis` 返回 105 笔交易、账户 `165291933`。

## 7. 常见问题

### 7.1 启动时报 `Port 8787 is already in use`

v0.5.8 还在跑。回到第 3 步，停掉旧实例后再启动 v0.6.0。

### 7.2 启动后只看到 7 笔 DEMO-* 交易

环境变量没生效，v0.6.0 退化到读自己 worktree 内置的 demo 数据库。检查：

```powershell
python -c "from app.core.config import get_runtime_paths; print(get_runtime_paths())"
```

期望输出 `database` 字段指向 `F:\文件\MT5复盘仪表盘\mt5-review-system\data\journal.sqlite`。

### 7.3 数据读取异常（缺字段）

schema 都是 v4，不应出现。如果出现，先确认 `data/journal.sqlite` 的 `schema_meta.version` 是 4：

```bash
sqlite3 data/journal.sqlite "SELECT * FROM schema_meta"
```

如果不是 4，先回到 v0.5.8 跑一次 `python -m app.data.bootstrap` 让它升级到 v4，再切回 v0.6.0。

## 8. MT5 EA 端点的处理

EA 通过 `config.local.json` 的 `local_bridge_endpoint`（默认 `http://127.0.0.1:8787/api/mt5/events`）往服务推事件。**只要 v0.6.0 实例跑在同一台电脑、监听同一端口（8787），EA 无需任何修改**。EA 会继续按原节奏推交易/资金/截图，新事件会通过 v0.6.0 的 importer 增量导入 `journal.sqlite`。

如果你把 v0.6.0 跑在不同端口或不同机器，编辑 `config.local.json` 的 `local_bridge_endpoint`，然后重启 MT5 EA 让它重读配置。

## 9. 回滚

如果 v0.6.0 验证后发现严重问题想退回 v0.5.8：

```powershell
# 1. 停掉 v0.6.0
Get-Process python -ErrorAction SilentlyContinue | Stop-Process -Force

# 2. 启动 v0.5.8
cd F:\文件\MT5复盘仪表盘\mt5-review-system
python run.py
```

v0.5.8 不支持 `MT5_REVIEW_DATA_DIR`，会按 `PROJECT_ROOT/data` 找 `data` 目录——正是你的真实数据。无需任何额外恢复操作，原始 105 笔交易、13251 条 raw_events、105 张截图都还在原位。

数据库**没有改动**——v0.6.0 启动时只会增量读取、不会破坏原数据。备份是兜底，不是必需。
