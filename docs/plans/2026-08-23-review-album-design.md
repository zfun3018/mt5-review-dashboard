# 复盘画册 MVP 实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在现有订单数据库和截图存储之上增加第二个“复盘画册”页面，按北京时间交易日展示截图，并使用现有分类和选项型自定义字段做简单标签筛选。

**Architecture:** 不改变现有数据库结构，不复制图片，不建立画册专用数据表。服务端直接查询 `trades`、`classification_options`、`custom_fields`、`custom_field_options`、`trade_custom_values`，复用现有交易序列化和截图 URL 规则；只在响应阶段计算北京时间日期、标签和日摘要。前端新增独立画册页面，复用现有原生 HTML/CSS/JS、订单详情入口和截图预览能力。

**Tech Stack:** Python `http.server`、SQLite、现有 `storage.py` 查询层、原生 HTML/CSS/JavaScript、Python `unittest`、Playwright。

---

## 一、已确认的范围

### 1. 第一版必须提供

- 从现有仪表盘进入“复盘画册”，并可返回订单流水。
- 以交易截图为主体，保持原始比例；不裁剪、不拉伸，小图不强制放大。
- 按北京时间的平仓日期分隔，日期内按平仓时间倒序排列；同一时间用交易 ID 稳定排序。
- 桌面端截图在左、信息在右；移动端信息移到截图下方。
- 展示品种、开仓/平仓时间、交易类型、交易策略、选项型自定义字段、手数、净盈亏、多空和复盘内容。
- 顶部提供：品种筛选、标签筛选、开始日期、结束日期、排序切换、清空筛选。
- 标签来源仅包括：
  - 交易类型选项；
  - 交易策略选项；
  - `field_type=single` 或 `field_type=multi` 的自定义字段选项。
- 无截图订单仍显示卡片，并提供进入订单详情补图的入口。
- 筛选结果数量、空结果状态、图片加载失败重试和当前条件清除。

### 2. 明确不做

- 不提供多空筛选。多空只作为卡片信息展示。
- 不提供文本型自定义字段筛选。文本复盘内容只展示，不做全文搜索。
- 不提供通用 `q` 搜索、复杂表达式、全文索引或服务端搜索引擎。
- 不复制或压缩原图，不把图片二进制写入数据库。
- 不新增画册专用表、不做 ETL、不做历史数据重建；不引入 React、构建工具或第三方画廊库。
- 不在 MVP 加入盈利/亏损、是否有复盘、是否有截图等快捷筛选；这些作为后续小版本候选。

### 3. 筛选语义

- 不同筛选维度之间使用 AND：品种、标签、起止日期必须同时满足。
- 同一标签维度内多选使用 OR，例如同一交易策略选择“突破”和“震荡”时命中任一即可。
- 不同标签维度之间使用 AND，例如交易类型“跟随”且策略“突破”。
- 多选自定义字段的交易值只要包含所选任一选项即可命中；单选字段使用等值匹配。
- 默认日期口径为北京时间平仓日期，开始和结束日期均包含当天。
- 只查询 `deleted_at IS NULL` 的有效订单。

## 二、为什么采用这个版本

该方案比当前已完成的截图替换功能复杂度略高，但明显低于动态全文字段筛选或数据模型重构。主要工作是新增一个只读查询接口、做轻量日期分组和前端展示；现有订单表、截图路径、分类稳定 ID、自定义选项值和软删除机制都可以直接复用。

因此第一版不需要迁移数据库，也不需要“重新处理”历史数据。服务端每次请求从现有 SQLite 读取有效订单，按已有 `_serialize_trade()` 规则生成交易对象，再附加 `album_date` 和展示标签。标签是响应时映射，不落库，避免字段改名或停用后产生两套数据。

## 三、数据与接口设计

### 1. 复用的现有数据

- `trades`：交易主体、时间、品种、方向、盈亏、复盘文本、截图路径、软删除状态。
- `classification_options`：交易类型和交易策略的稳定 ID、显示名、颜色、启用状态。
- `custom_fields`：字段名称、类型和顺序。
- `custom_field_options`：单选/多选字段的选项名称和颜色。
- `trade_custom_values`：每笔交易保存的选项 ID 或多选 JSON 值。
- `data/screenshots`：原图文件；继续使用现有 `/media/...` URL 和缺图判断。

### 2. 新增接口

新增 `GET /api/review-album`，建议参数：

```text
start=YYYY-MM-DD
end=YYYY-MM-DD
symbol=EURUSD,XAUUSD
tag=trade_type:follow,strategy:breakout,field:12:option-3
sort=desc|asc
page=1
page_size=24
```

不接受 `side`、`q` 或文本字段筛选参数。未知标签、未知字段或非法日期返回 400，并带可读错误；空标签等同于未筛选。

响应建议：

```json
{
  "filters": {"start": "", "end": "", "symbol": [], "tags": [], "sort": "desc"},
  "total": 48,
  "page": 1,
  "page_size": 24,
  "days": [
    {
      "date": "2026-08-21",
      "order_count": 10,
      "net_pnl": 19.5,
      "trades": [
        {
          "id": "...",
          "album_date": "2026-08-21",
          "album_tags": [
            {"key": "trade_type:follow", "label": "交易类型 / 跟随", "color": "#2bd4ff"}
          ],
          "screenshot_url": "/media/screenshots/...",
          "screenshot_missing": false
        }
      ]
    }
  ],
  "available_filters": {
    "symbols": ["EURUSD", "XAUUSD"],
    "tags": [
      {"key": "trade_type:follow", "label": "交易类型 / 跟随", "dimension": "trade_type"},
      {"key": "field:12:option-3", "label": "错误类型 / 追单", "dimension": "custom_field"}
    ]
  }
}
```

### 3. 查询实现约束

- 在 `storage.py` 增加 `query_review_album()`，先过滤 `deleted_at IS NULL`，再应用日期和品种条件，最后在同一查询结果上执行标签匹配。
- 优先复用现有 `query_trades()` 的日期转换、净盈亏和自定义值读取逻辑；不要在前端从完整 bootstrap 数据重新计算。
- 标签匹配只解析稳定 ID：分类值直接比较；单选值比较一个 ID；多选值解析现有 JSON 数组。不得按显示名称匹配，避免改名破坏历史筛选。
- 只把当前仍存在且属于单选/多选字段的选项放进可用标签；历史停用的交易类型/策略若被历史交易使用，仍显示在卡片中，但不作为新筛选项。
- 自定义字段被删除后，历史交易中的孤立值不应使接口失败；该值不生成筛选标签，详情中按现有兼容逻辑处理。
- 截图路径为空或文件不存在时返回卡片，设置 `screenshot_missing=true`，不能静默丢弃订单。
- 分页按交易卡片数量执行；日期组可跨页，响应中的 `date` 让前端能够正确渲染日期标题。

## 四、前端页面方案

### 1. 文件变更

新增：

- `mt5-review-system/web/album.html`
- `mt5-review-system/web/album.js`
- `mt5-review-system/web/album.css`（或在现有 `styles.css` 中使用完整的 `.album-*` 命名空间）

修改：

- `mt5-review-system/web/index.html`：增加“复盘画册”入口。
- `mt5-review-system/web/app.js`：只增加入口或跳转，不复制订单流水渲染逻辑。

### 2. 页面布局

```text
导航
筛选工具栏：品种 | 标签 | 开始日期 | 结束日期 | 排序 | 清空
结果摘要：交易数、日期数、当前净盈亏
日期分组：2026-08-21
  交易卡片：截图（自然比例） | 核心信息、标签、复盘摘要、打开订单
日期分组：2026-08-20
```

桌面端图片列使用 `minmax(0, 1fr)`，信息列约 280-360px；图片设置 `width: auto; max-width: 100%; height: auto`，避免主体区域被固定高度或 `object-fit: cover` 破坏。移动端单列排列，长复盘默认折叠 5-7 行。

### 3. 交互和状态

- 筛选变更后防抖请求，重置页码；筛选状态同步到 URL，刷新后可恢复。
- 标签按字段分组展示，组内可多选；界面明确“同组任一，跨组同时满足”。
- 点击图片复用现有大图预览；`Esc` 关闭，左右键切换当前结果。
- 点击“打开订单”进入已有订单详情；缺图卡片直接提供补图入口。
- 接口失败保留上一次成功内容，显示局部错误和重试；空结果提供一键清除。

## 六、测试与验收标准

### 后端

- 软删除订单永远不出现在画册。
- 同一标签组多选为 OR，不同标签组为 AND。
- 文本型自定义字段既不出现在标签列表，也不能作为筛选参数。
- 多空字段只返回并展示，不影响查询条件。
- 日期按北京时间平仓日分组，范围边界包含当天。
- 改名后的分类仍按稳定 ID 命中；停用分类不出现在新筛选列表，但历史卡片标签不丢失。
- 空截图路径和失效截图路径均保留卡片，并正确返回缺图状态。

### 前端

- 桌面端信息在右侧，移动端信息在下方；无横向溢出。
- 图片不裁剪、不拉伸，长宽比例稳定，长复盘不撑坏卡片。
- 筛选、清空、刷新和复制 URL 后恢复状态均可用。
- 图片预览、键盘关闭/切换、订单详情跳转和补图入口可用。

## 八、暂不纳入但值得记录的后续问题

- 是否需要按账户、会话或品种分组：目前数据库已有字段，但用户尚未要求，先不增加筛选器。
- “实际大小”需要一个可视上限：MVP 采用自然比例 + 容器最大宽度，点击预览查看原图。
- 原图很大时首屏性能可能下降：先用懒加载观察真实数据，再决定是否进入 v0.5.0 缩略图。
- 画册是否要导出、打印、分享或批量下载：这些会引入权限和文件处理问题，暂不纳入。
